# Портфолио для первых заказов

Подготовить три небольших личных демо под выбранные задачи:

1. Telegram-бот: команда, форма заявки, сохранение в SQLite, уведомление. Видео 30–60 секунд, скриншот и README с запуском.
2. Парсер открытых тестовых данных: сбор, очистка, экспорт CSV, повторный запуск без дублей. Скриншот входа и результата, инструкция.
3. API-интеграция: webhook, валидация, защита от дублей, обработка ошибки. Видео успешного запроса и повтора.

Для каждого кейса: задача, конкретный результат, стек, ссылка на реальный репозиторий или демо, 2–3 скриншота. Помечать «личный демонстрационный проект». Не приписывать заказчиков, оплату или отзывы.

DEVELOPER_PORTFOLIO уже используется генератором откликов. После подготовки добавить реальные кейсы в эту переменную окружения: название | личное демо | функции | стек | ссылка. Пока ссылки нет, не публиковать выдуманную.

После оплаченного заказа добавить согласованный с заказчиком обезличенный кейс. Запрашивать честный отзыв после сдачи, без обмена скидки на положительную оценку.

# Отбор

По умолчанию REVIEW_FIRST_MODE=true: рейтинг минимум 4.8/5, минимум один подтверждённый выполненный оплаченный заказ, понятный объём до 8 рабочих часов. Бюджет имеет вес 5%, простота 35%, совпадение навыков 25%, заказчик 25%, конкуренция 10%. Старые обученные веса не переопределяют эту стратегию.

Неизвестная история заказчика блокирует отбор. Парсер Kwork принимает только явно подписанные рейтинг покупателя по шкале 5 и выполненные оплаченные заказы. Отзывы продавца, число опубликованных или просто закрытых проектов не доказывают оплату. Реальная разметка профиля требует проверки; если площадка не показывает эти данные, автоматический отбор будет пропускать такого покупателя.

Существующая пауза при исчерпании коннектов сохраняется. Для работающего процесса нужен перезапуск после изменения кода. Старые подготовленные отклики автоматически не пересматриваются; их следует заново проверить перед отправкой.
