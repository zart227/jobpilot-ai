# Входящие сообщения Kwork без ID

Если Kwork передаёт ID сообщения, он используется как прежде. Без ID формируется устойчивый ключ из пользователя, времени и полного очищенного текста. При повторном получении старые записи БД сопоставляются по пользователю, времени из старого ключа и точному тексту; старые данные не переписываются.

Когда времени нет, в одной выдаче есть одинаковые сообщения без ID или старый JSON содержит совпадающее время, но запись не удаётся сопоставить с БД, сообщение не обрабатывается автоматически. Проверка inbox возвращает `identity_ambiguities` с причиной, пользователем и при наличии временем; журнал содержит предупреждение с количеством. Это не отдельное Telegram-уведомление и не постоянная очередь ручного разбора: оператору требуется просмотреть соответствующий диалог. Сам текст в отчёт не добавляется.

Полностью различить два одинаковых сообщения без ID и с одним временем невозможно, если площадка показала только одно из них. Старые записи без пользователя или полного текста также могут не сопоставиться. Неоднозначные случаи ставятся в **`identity_ambiguities`** и порождают durable **`ops_alert`** outbox (idempotent key `inbox_identity_ambiguity:*`) для операторского разбора; см. **`test_kwork_inbox_identity.py`**. Смешанный rollout старых и новых poller по-прежнему запрещён.

Перед согласованным развёртыванием требуется остановить все старые poller/worker-процессы, сохранить резервные копии БД и JSON состояния и проверить переход в изолированной копии. Старые процессы используют случайный hash и при одновременной работе с новым кодом могут создать дубликаты; смешанная версия не поддерживается. Этот документ не разрешает запуск и изменение рабочей среды.
